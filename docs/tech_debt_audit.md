# Технічний Аудит та План Рефакторингу (Technical Debt Plan)

Цей документ підсумовує всі 9 інфраструктурних проблем, знайдених під час повного рев'ю папки `src/`, та пропонує план їх виправлення для підготовки бекенду до Production.

## Виявлені Проблеми (Звіт про Аудит)

### 🔴 Критичні проблеми (Ризик падіння сервера або втрати даних)
1. **Витік пам'яті (OOM) при завантаженні PDF (`upload.js`)**
   - **Суть:** Використання `multer.memoryStorage()` дозволяє завантажити до 50 файлів по 10 МБ в оперативну пам'ять (500 МБ на запит). Це гарантовано призведе до падіння сервера при навантаженні.
   - **Рішення:** Замінити на `multer.diskStorage()`, парсити файли з тимчасової папки та одразу видаляти їх.

2. **Стан гонитви (Race Condition) в експорті (`export.js`)**
   - **Суть:** Кожна генерація ШІ-коментаря повністю зчитує і перезаписує файл `export.json`. При одночасних запитах файли перезапишуть один одного, що призведе до втрати даних. При зростанні розміру файлу це заблокує Event Loop.
   - **Рішення:** Видалити синхронізацію в реальному часі. Зберігати дані тільки в SQLite. Генерацію `export.json` робити **на льоту** виключно при виклику роута `GET /api/export`.

3. **Забивання Event Loop (`search-engine.js`)**
   - **Суть:** Використання `Promise.all` для генерації векторів одночасно на 200+ записів навантажує CPU на 100% і "вішає" Node.js.
   - **Рішення:** Замінити на `for...of` цикл (обробка по одному) або впровадити архітектуру з `PLAN_v6` (збереження векторів у БД).

4. **Зависання мережевих запитів (`hn.js`, `reddit.js`)**
   - **Суть:** Відсутність таймаутів у глобальному `fetch`. Якщо Reddit/HN не закриє з'єднання, запит зависне назавжди, зупинивши `scheduler`.
   - **Рішення:** Додати `AbortController` з таймаутом (наприклад, 10 секунд) до всіх зовнішніх HTTP-запитів.

### 🟡 Логічні та Архітектурні проблеми
5. **Ризикований HTML парсинг (`djinni.js`)**
   - **Суть:** Парсинг за допомогою Regex та `split('class="job-item "')` зламається, якщо Djinni змінить бодай один пробіл чи клас.
   - **Рішення:** Використати бібліотеку `cheerio` для надійного парсингу DOM-дерева.

6. **Галюцинації ШІ (`generate-comment.js`)**
   - **Суть:** Промпт каже ШІ *"use the same writing style as in the example"*, але приклад не надається. Також є граматичні помилки у промпті.
   - **Рішення:** Виправити граматику та переписати системний промпт на більш чіткий рольовий (без міфічних "прикладів").

7. **Брак даних для супровідного листа (`generate-cover.js` + `djinni.js`)**
   - **Суть:** Промпт очікує `item.metadata.company`, але парсер Djinni не витягує компанію з HTML. В результаті ШІ завжди пише листи для "Unknown company".
   - **Рішення:** Оновити `djinni.js`, щоб він парсив назву компанії.

8. **"Сліпий" Graceful Shutdown (`shutdown.js`)**
   - **Суть:** При зупинці сервера використовується жорсткий `setTimeout` на 5 секунд. Сервер "чекає" навіть якщо роботи немає. Але водночас він може перервати запис в БД, якщо фонова задача триває довше.
   - **Рішення:** Рефакторинг. Зробити так, щоб скрипт зупинки перевіряв статус `scheduler.isRunning` і чекав його безпечного завершення, а якщо з'єднань немає — виходив миттєво.

9. **Неконтрольовані фонові задачі (`sync.js`)**
   - **Суть:** Роут викликає `scheduler.runCycle().catch(...)` без `await`. Це створює "відв'язаний" Promise, який не контролюється життєвим циклом Express.
   - **Рішення:** Вирішується інтеграцією з пунктом 8 (Graceful Shutdown має знати про стан `runCycle`).
